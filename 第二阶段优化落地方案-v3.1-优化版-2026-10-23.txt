# 小6智能体 · 第二阶段优化落地方案 v3.1（优化版）

日期：2026-10-23
定位：在 v3 基础上按真实代码、风险和验收重新排期。

## 一、总体结论

- 方向可行，但不建议一次性承诺 49 天全量开发。
- 改成 3 个里程碑 + 每阶段独立验收。
- 第一里程碑 10 天，先做最能形成产品闭环的 Agent 能力。
- 全部完成预计 45～55 人日。
- 远程 Skills 市场、远程 Web 控制台、多模态放在后续阶段。

## 二、先修正 4 个技术判断

1. coder_pro 不是从零重写。已有 CodeAgent 已包含探索、patch、审批、测试、回修、回滚和 git 快照。P0-1 改为 2 天增量完善，重点补 Plan/Act 可视化、任务事件和验收测试。
2. web_agent 当前链路有缺口。browse() 只做打开和截图，还调用了不存在的 multimodal.describe()。先做 DOM-first 动作循环：打开页面、提取交互元素、选择动作、执行、验证、重试；视觉模型只作为可选增强。
3. Skills 不要 markdown 自动转 zip。新增统一 SkillRegistry，支持捕获的 markdown、导入的 x6skill、启用禁用、来源和版本；同时补 zip-slip、解压体积、manifest、签名和失败回滚。
4. MCP 市场 1 天只够目录增强。现有 mcp_dialog 已有 HTTP/stdio、预置服务器、一键安装、测试、重连和信任管理；真正缺的是远程目录、版本、来源校验、更新和卸载。

## 三、推荐实施顺序

### M0：现状审计与接口修复（1 天）
- 修 web_agent 调 multimodal.describe() 的接口错误
- 统一截图返回类型
- 确认 coder_pro / web_agent / task_runtime / skill_capture 的真实入口
- 建立本阶段验收用例

### M1：Agent 可用闭环（9～10 天）
| 任务 | 时间 |
|---|---:|
| coder_pro Plan/Act 增量完善 | 3 天 |
| web_agent DOM-first 动作循环 | 4 天 |
| task_runtime 到 skill_capture 自学习 MVP | 2 天 |
| MCP 精选目录 MVP | 1 天 |

### M2：技能管理与真实评测（12～15 天）
| 任务 | 时间 |
|---|---:|
| SkillRegistry + Skills GUI | 5 天 |
| SWE-bench 小样本真实执行 | 5～7 天 |
| 本地 Web 控制台 MVP | 3～4 天 |

### M3：多模态与远程市场（15～20 天）
| 任务 | 时间 |
|---|---:|
| 图片选择、粘贴、拖拽 | 3 天 |
| 图片消息模型和缩略图 | 2 天 |
| OpenAI / Anthropic / Gemini 视觉适配 | 5 天 |
| 本地 Ollama 视觉模型 | 2 天 |
| 视觉降级与测试 | 2 天 |
| 远程 Skills / MCP 市场 | 5～8 天 |

## 四、关键验收标准
- coder_pro：真实小项目完成发现问题、修改、测试、回滚
- web_agent：完成搜索、点击、填表三类真实网页任务
- 自学习：任务完成后生成待确认技能，确认后可在下次类似任务注入
- Skills：可导入、导出、启用、禁用、删除，损坏包必须拒绝
- SWE-bench：至少跑通 5～20 个真实小样本，不能是占位数据
- Web 控制台：只监听 localhost，必须有一次性 token，不允许裸奔
- 多模态：支持图片选择与预览，按模型能力路由，失败可降级

## 五、总排期
| 阶段 | 时间 | 目标 |
|---|---:|---|
| M0 | 1 天 | 接口审计和基线修复 |
| M1 | 9～10 天 | Agent 可用闭环 |
| M2 | 12～15 天 | 技能管理、真实评测、本地控制台 |
| M3 | 15～20 天 | 多模态、远程市场 |

总计约 37～46 人日，加 20% 缓冲约 45～55 人日。

一句话：v3 方向对，但改成 M0→M1→M2→M3 的分阶段版本才真正可落地；先做 10 天 Agent 闭环最稳。
