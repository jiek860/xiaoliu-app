## 安全加固实施记录

日期：2026-10-19  
对应方案：`docs/20_优化路线与实施记录.md`（第一部分安全底座）

### 一、已完成

#### 1. 飞书 Webhook / Secret 加密

- `config.default.json` 中的 `feishu_webhook`、`feishu_secret` 改为 `x6enc:v1:` AES-GCM 密文。
- 新增 `core/default_secrets.py`：只保存密文；运行时才还原到内存。
- `core/config.py` 的 `DEFAULTS` 不再包含明文，改为运行时解密默认值。
- `core/secret_store.py` 读取配置时先解 DPAPI、再解应用级默认密文。
- 首次生成 `data/config.json` 时仍然是 DPAPI 保护的本机配置。

说明：这是静态加密/防明文扫描方案。程序调用飞书接口时必须在内存里拿到明文，因此无法抵御能逆向二进制或 dump 进程内存的攻击者。若需要更强保护，应改为服务端代理发送或使用系统凭据库。

#### 2. MCP 本地服务鉴权

- `/tools`、`/call` 必须携带 `Authorization: Bearer <token>`。
- token 每次进程启动随机生成，仅同进程 `mcp_client` 自动读取，不落盘。
- 增加 Host、Origin、Content-Type、请求体大小校验。
- 默认 HTTP 工具表移除 `run_code`。
- 代码执行、电脑控制、文件写入等危险方法默认禁止通过 HTTP 调用；需要显式设置 `mcp_allow_dangerous_tools=true`。

#### 3. 工具权限默认拒绝

- 新增 `core/security_policy.py`。
- `code_run`、`fs_read`、`fs_edit`、`computer`、`browser`、`shell` 等内置工具登记风险级别。
- `code_run`、`fs_edit`、`shell` 受危险规则开关控制。
- 没有确认界面时，非只读工具一律拒绝。
- 确认框展示具体参数、路径、命令或代码摘要。
- 机器人等远程会话默认禁用工具：`bot_allow_tools=false`。
- MCP 外部工具调用同样需要确认。

#### 4. 路径安全

- 新增 `core/path_safety.py`，统一使用 `realpath + commonpath`。
- 修复电脑控制白名单的字符串前缀绕过。
- 加固 `file_upload`、`knowledge_qa`、`backup`、`browser_session`、`plugin_market`、`module_server` 的路径拼接。
- 备份名、会话名、插件文件名不能再利用 `..` 越界。

#### 5. 插件与更新安全

- 插件只有 sha256、没有 RSA 签名时不再视为可信，默认拒绝。
- 插件下载文件名必须是单级 `.py`，落点必须位于 `modules/installed` 内。
- 下载先写临时文件，成功后再原子替换。
- 更新包路径检查改为 realpath，并拒绝目录穿越。
- `module_server` 首页对清单字段做 HTML 转义，下载路径使用安全 join。

#### 6. 本地服务与确认机制

- `Trunk.confirm()`、`AutoUpdater.ask_confirm()`、`ComputerController._confirm()` 改为 fail-closed。
- `bot_server` 增加随机 token、Host/Origin、Content-Type、请求体大小限制。
- `mcp_stdio` 子进程强制 `PYTHONIOENCODING=utf-8`。

#### 7. 加密、备份与授权

- `memory_crypto` 导出升级为 `X6MEM2 + salt + nonce + AES-GCM`，密码使用 PBKDF2-HMAC-SHA256 200000 次；兼容旧 AES/XOR 文件导入。
- `core/crypto.py` 新数据使用 AES-GCM，旧 XOR 仅保留只读兼容；文件加密不再静默写 XOR。
- `backup.export` 没有 7-Zip 时改用 Python AES-GCM + PBKDF2 加密，不再退化成明文 zip；不返回密码。
- `Auth.login` 会重新校验激活码，不能只改本地 `users.json` 的 `activated` 字段。
- Ollama 安装包启动前校验 Windows Authenticode 签名。

## Agent 时代新增安全边界（2026-10-19）

### 代码修改
- 所有 patch 必须先经过文件和 hunk 审批。
- patch 带 `base_hash` 时，文件在应用前被改动则拒绝覆盖。
- hunk 原文必须唯一匹配，出现 0 次或多次都拒绝。
- 应用前备份原文件；失败整体回滚；支持一键回滚本轮修改。
- Git dirty 工作区在修改前另存 diff 到 `data/patch_backups`。
- 代码 Agent 默认不自动建 Git 分支；当前只做状态记录和 dirty diff 备份。

### 电脑操作
- 动作必须经过 `core/action_schema.py` 校验。
- 高风险动作（shell、写文件、编辑文件）默认要求确认。
- 每个动作可声明验证条件：窗口标题、控件可见、文件变化、退出码、截图变化。
- 操作记录、截图和回放文件可能包含屏幕内容，应按隐私数据处理，不要随日志自动外发。
- 命令执行仍保留白名单、超时、危险命令确认和审计。

### MCP / 后台进程
- MCP stdio 子进程进入活动中心，可看到名称、命令、工具数、PID。
- 已预导入 stdio 传输层，降低多线程并发 import 导致的 Windows 原生崩溃风险。
- MCP 子进程停止时自动更新活动状态。

## 2026-10-20 数据迁移与插件 API 安全补充

- 旧数据迁移前自动备份到 `data/_migrations/`，失败不覆盖原文件；
  JSONL 无法解析的坏行原文写入 `.bad_lines`，不会静默删除。
- SQLite 迁移使用事务与 `x6_meta` 版本表；降级数据（比程序新）只警告不自动改。
- 插件安装保持先验签、后执行的顺序；新增 `api_version` 校验和 AST 依赖边界检查。
- 第三方插件禁止依赖 `core.trunk`、`core.data_schema`、`core.data_migrations`、
  `core.secret_store`、`core.release_sign` 等私有/敏感实现。
- `first_party: true` 只用于官方随包模块；第三方插件不得依赖内部集成层。
