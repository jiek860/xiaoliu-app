## 三、文档分类合并规范（新增文档必须先读）

1. 新内容先判断归属：对照上面 10 个合订本，找到最接近的主题；
2. 属于某类 → **追加到该合订本末尾**（新开 `## 附录：<主题>（<日期>）` 章节），
   并在该合订本头部的「合并来源」一行补上主题名；
3. 只有同时满足「运行时读取」「跨仓库发布」「需要独立签名」三种情况才允许新建文件；
4. 确实需要新建时，编号取所属类别的下一个号段（如 `30x_`、`10x_`），并在本索引登记；
5. 每次新增/合并后，同步更新本文件「更新日期」与对应行的「维护要求」；
6. 不允许在 docs/ 根下堆积一次性方案、临时报告、单批次记录 —— 一律进合订本附录。

## 四、维护规则

1. 运行时必须读取的文件不能删：`docs/用户协议.txt`、`docs/隐私政策.txt`、`docs/模块星图.html`。
2. 修改协议文本必须同步：根目录同名文件 + `core/agreement.py` 的版本号。
3. 架构或核心模块变化时同步：`ARCHITECTURE.md`、`docs/00`、`docs/30`。
4. 新增能力或规则时同步：`docs/30`（`tests/test_docs_consistency.py` 会校验能力数）。
5. 兼容性 / 数据 / 插件 API 变化时同步：`docs/70`、`使用说明-小白版.txt`、
   `gui/tutorial_dialog.py`、`gui/onboarding_wizard.py`。
6. 发布前运行：
   ```powershell
   py -3 -m pytest tests/test_docs_consistency.py tests/test_user_docs_intact.py -q
   py -3 tools/check_version.py
   py -3 tools/check_plugin_repo.py
   py -3 tools/check_plugin_api.py
   py -3 tools/pre_commit_check.py --full
   ```
7. 文档 / 教程同步范围：根目录 `README.md` / `README_EN.md` / `ARCHITECTURE.md` /
   `CHANGELOG.md`；用户文档 `使用说明-小白版.txt` / `FAQ.txt` / `模型教程.txt` /
   `检测手册.txt` / `部署步骤.md` / `开发者须知-密钥与发版.md`；程序内教程
   `gui/tutorial_dialog.py` / `gui/onboarding_wizard.py`；docs 10 个合订本。
   打包源由 `tools/sync_package.py` 同步到 `E:\xiao6-package`。
