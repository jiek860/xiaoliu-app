## 四、问题清单与优先级

### P0：发布前必须做

1. 在 GitHub 实际跑通 Windows x Python 3.10/3.11/3.12 兼容矩阵。
2. 在干净 Windows 10/11 虚拟机执行安装器、首次启动、登录、配模型、聊天全流程。
3. 做一次真实 Ollama 本地模型和云端模型的端到端回复测试。

### P1：高收益改进

4. 收敛 `shell=True`：
   - 能用 argv 数组的改为数组；
   - 应用启动用白名单校验 + `os.startfile` / `subprocess.Popen([...])`；
   - 沙箱命令继续保留 shell 时必须经过权限中心、命令白名单和审计。
5. 修复 `build_portable.py --out` 相对路径处理。
6. 升级本地可选依赖，尤其是 Pillow；不要把开发/Jupyter 包混进可选运行环境。
7. 提高低覆盖模块测试：computer_window_tools、computer_file_tools、
   chat_mixin、task_center_dialog、security_center_dialog、voice.py。

### P2：持续治理

8. 仍有 174 处 `except Exception: pass` 形态，多数已有注释并被守卫接受，
   但建议持续收敛为带日志/返回错误的处理。
9. PyInstaller 有 402 条 missing-module warning，多为可选/Unix/开发包；
   建议在干净构建环境重新打包，并检查 Qt 插件目录。
10. `install.bat` 仍写Python 3.10+，建议改成3.10/3.11/3.12，
    3.13 未验证，避免用户装 3.13 后误判为受支持。

## 必需检查（Branch protection required checks）

在 GitHub 仓库设置中把以下检查设为 required status checks，并启用：

- Require a pull request before merging
- Require status checks to pass before merging
- Require branches to be up to date before merging
- Do not allow bypassing the above settings

稳定检查名：

| Check | Workflow | 说明 |
|---|---|---|
| `static` | `.github/workflows/test.yml` | Ruff、Mypy、文件长度、workflow 供应链策略 |
| `test` | `.github/workflows/test.yml` | 全量测试、覆盖率、E2E、守卡 |
| `ci-required` | `.github/workflows/test.yml` | static + test 汇总 |
| `compat-required` | `.github/workflows/compat-matrix.yml` | Windows / Python 3.10-3.12 矩阵 |
| `windows-build-required` | `.github/workflows/build-windows.yml` | PyInstaller 构建、产物 hash 清单 |
| `portable-required` | `.github/workflows/build-portable.yml` | Windows/Linux/macOS 便携包 |
| `security-required` | `.github/workflows/security.yml` | secret scan、Bandit triage、pip-audit、license、SBOM（Dependabot + pip-audit 作为依赖审查门禁） |
| `codeql-analyze` | `.github/workflows/codeql.yml` | CodeQL 静态分析 |
