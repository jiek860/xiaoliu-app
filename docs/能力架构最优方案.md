# 小6 能力架构最优方案 v2（可落地版）

> v1 的缺口：以为升级 `manifest.json` 就够了。
> **实测发现 72 个登记模块里有 24 个住在 `core/`，它们根本没有清单条目** ——
> 而 24 条可撤按钮里 16 条的目标正好在 core。所以 v2 补上了 core 级注册表。
>
> v2 同时把"能减多少"算准了：**54 个入口 → 22 个，减 32 个（-59%）**，
> 并给出**防止回弹的预算守卫**——否则减完几个月又长回来。

## 一、诊断（全部实测）

| 指标 | 实测 | 问题 |
|---|---|---|
| 登记模块 | 72 个 | — |
| ├ 实现在 `modules/installed` | **48 个** | 有签名清单条目 ✅ |
| └ 实现在 `core/` | **24 个** | **没有清单条目** ❌ ← v1 漏了 |
| 能靠说话触发的 | **7 个（10%）** | 只在 `tool_caller` 的 19 个工具里 |
| 静态扫不到调用点的 | **44 个** | 天气/待办/笔记/日历… 只能靠人点 |
| GUI 控件创建 | 114 处 / 27 文件 / 14 弹窗 | — |
| 手写入口表 `ACTIONS` | **24 条** | 猜参数调用（`((), (7,), (30,), (20,))`） |
| `tool_caller` 工具带 schema | **19 / 19 = 100%** | 所以它们能被模型调用 |
| `ACTIONS` 表带 schema | **0 / 24 = 0%** | 所以只能人点 ← **分水岭** |

| 🟢 **可用文字参数替代** | **23** | 参数全是 `out_path` / `days` / `topic` / `message` / `count` 这类 |
| 🟡 **必须保留 UI** | **1** | `memory_crypto.export_encrypted(out_path, password)` —— 密码不能打进聊天（会进日志） |

### 按钮预算

| 位置 | 现在 | 目标 | 撤掉的 | 保留理由 |
|---|---|---|---|---|
| **实用工具面板** | 24 | **0** | **−24** | 23 条可对话化；密码那条改**掩码弹窗** |
| **+ 号菜单** | 8 | 5 | −3 | 留：上传文件/区域截图/送编辑器/朗读开关/引用选中文本 |
| **功能中心** | 9 | 4 | −5 | 留：知识图谱(要可视化)/日志中心/系统自检/机器人 |

| 输入行 | 4 | 4 | 0 | 界面操作 |

## 三、落地机制：**双来源能力注册表**

因为模块分两处住，注册表也要两个来源，最后由一个模块合并：

```
┌─ 来源 A：插件模块（48 个）─────────────────────────┐
│  模块里声明 TOOLS → rebuild 写进 manifest.tools      │
│  → RSA 签名保护 → 随市场分发                        │
└────────────────────────────────────────────────────┘
                        ↓
              core/module_caps.py   ← 合并成一个工具表
                        ↑
┌─ 来源 B：core 模块（24 个）─────────────────────────┐
│  core/core_caps.py 里集中声明（它们不是插件，        │
│  没有清单，但同样可以声明"我能被这样调用"）           │
└────────────────────────────────────────────────────┘
                        ↓
        tool_caller = 内置工具 + 来源A + 来源B
                        ↓
              模型能调用全部 72 个模块
```

### 3.1 插件模块的声明（来源 A）

模块里加一个类属性：

```python
class ImageOcr(BaseModule):
    NAME = "image_ocr"

    TOOLS = [
        {"name": "ocr_read", "method": "recognize",
         "desc": "识别图片里的文字",
         "args": {"image_path": "图片路径，如 D:\\a.png"},
         "readonly": True},
        {"name": "ocr_history", "method": "get_history",
         "desc": "以前识别过的图片",
         "args": {"count": "要几条，默认 10"}},
    ]
```

`tools/rebuild_modules_repo.py` 加一行把它写进清单（和现有的 `desc`/`group`/`button`
一样走"模块声明优先，旧清单保留"的逻辑）：

```python
entry["tools"] = getattr(cls, "TOOLS", None) or (base or {}).get("tools") or []
```

签名链自动覆盖它——**能力声明天然防篡改**。

### 3.3 合并器

`core/module_caps.py`（照抄 `core/module_buttons.py` 的结构：不依赖 Qt、可单测、
任何异常返回空）：

```python
def load_tools(base):
    """合并三处来源，返回统一的工具表"""
    out = {}
    # 来源 A：签名清单（插件模块）
    for m in _read_manifest(base):
        if not _installed(base, m):
            continue
        for t in (m.get("tools") or []):
            out[t["name"]] = {
                "desc": t.get("desc", ""),
                "mod": m["name"], "method": t["method"],
                "args": t.get("args") or {},
                "readonly": bool(t.get("readonly")),
                "confirm": bool(t.get("confirm")),
                "danger": bool(t.get("danger")),
            }
    # 来源 B：core 声明
    try:
        from core.core_caps import CORE_CAPS
        for t in CORE_CAPS:
            out[t["name"]] = {k: v for k, v in t.items() if k != "name"}
    except Exception:
        pass
    return out
```

`tool_caller.__init__` 改成：

```python
self.tools = { ...内置 19 个... }
self.tools.update(module_caps.load_tools(self.trunk.base))   # ← 一行接上
```

## 四、命令面板（撤按钮后的可达性保障）

撤按钮的前提是**有替代入口**，否则用户找不到功能。

### 设计

| 项 | 设计 |
|---|---|
| 唤起 | `Ctrl+K`（也支持在输入框打 `/`） |
| 数据源 | `module_caps.load_tools()` + 内置动作 + 能打开的对话框 |
| 交互 | 模糊搜索 → 回车执行；带参数的能力**内联追问**（不跳窗） |
| 带参数的处理 | `migration.export` 需要 `out_path` → 面板里出现一个输入行，或直接把句子补全到聊天框（`导出到 ______`）|
| 已有基础 | `gui/module_tools_dialog.py` **已经有搜索框**（P4 加的），把它升级即可，不用从零写 |

### 为什么这能减按钮而不是搬家

因为**一个面板承载 30+ 条能力**，而且是"按需出现"的——
它不像 24 个按钮那样**常驻占屏幕**。视觉噪音从"常驻 N 个"变成"0 个常驻 + 1 个快捷键"。

## 五、防回弹：按钮预算守卫（**这是"落地"的关键**）

没有守卫的话，减完几个月又会有人"顺手加个按钮"长回去。

新增 `tools/check_buttons.py`：

```python
"""统计 GUI 控件数并与预算比对

预算写在 tools/button_budget.json，超了就失败。
和 check_version.py 一样，挂进 check.bat，提交前就拦住。
"""
BUDGET = {
    "total": 60,                    # 从 114 降到 60
    "gui/module_tools_dialog.py": 2,   # 那 24 条撤到只剩搜索框+关闭
    "gui/build_ui.py": 11,             # 主窗口输入行不动
    "gui/settings_dialog.py": 11,      # 设置不动
}
```

输出形如：

```
按钮预算检查
  gui/module_tools_dialog.py    2 /  2  ✅
  gui/build_ui.py              11 / 11  ✅
  gui/center_dialog.py         11 /  4  ❌ 超 7
  ─────────────────────────────────────
  合计                         68 / 60  ❌ 超 8
加按钮请先说明为什么「说一句」替代不了它。
```

**这条比方案本身更重要**——它把"一次性清理"变成"可持续的约束"。

## 六、实施路线（七批，每批可独立验证 + 可回滚）

| 批次 | 做什么 | 验收 | 回滚 |
|---|---|---|---|
| **1** | `core/core_caps.py` + `core/module_caps.py` + `tool_caller` 接一行 | 手工加一条 → 说一句能触发 | 删文件即回滚（零行为变化） |
| **2** | 把 24 条 `ACTIONS` 改写成 `CORE_CAPS` 声明 | 24 条全部能靠说话触发 | 同上 |
| **3** | 插件模块 `TOOLS` 声明（先 10 个高频） | `weather`/`todo`/`notes`/`calendar` 能说 | 删声明即回滚 |
| **4** | 命令面板（Ctrl+K） | 关键词能跳到任意能力 | 保留旧面板不动 |
| **5** | **`tools/check_buttons.py` 预算守卫** | 挂进 check.bat | — |
| **6** | **撤按钮**：实用面板 24 → 0，功能中心 9 → 4，+菜单 8 → 5 | 预算达标 | `config["旧按钮面板"]=true` 可回退 |
| **7** | 模式预设（日常/干活/编程） | 工具表随模式变化 | — |

**批次 6 的回滚开关**（关键，否则不敢撤）：

```python
# data/config.json
"旧按钮面板": false    # true = 恢复那 24 个按钮（保留一个版本周期再删代码）
```

**先双通道（批次 1-4）跑一段时间，确认对话路径真的好用，再撤（批次 6）。**
最坏情况只是"多留了几个按钮"，而不是"功能找不到了"。

## 七、和豆包 / DSH 的对应关系

| 学到什么 | 来自 | 小6 怎么落 |
|---|---|---|
| 技能要能被模型**统一调用** | DSH（工具都有 schema） | `manifest.tools` + `CORE_CAPS` |
| 技能要**可发现** | 豆包（技能列表） | 命令面板 Ctrl+K |
| 危险能力要**能按技能隔离** | 豆包（虚拟桌面沙箱） | `readonly/confirm/danger` 三级 |
| 原语要能**组合出长尾** | DSH（19 个原语） | L1 已加厚（`fs_*`/`browser`/`ui_*`/`shell`） |
| 工具多了要**按场景收窄** | DSH `preset-*` + 豆包"工作任务" | 批次 7 模式预设 |
| **约束要可执行，不靠自觉** | —（小6 自己的教训） | 预算守卫 `check_buttons.py` |

## 八、为什么这次能真落地

v1 只是个方向，v2 补上了三件让它能落地的东西：

1. **补上了 core 那 24 个模块的路径**——否则 24 条可撤按钮里 16 条根本够不着
2. **算准了数字**（54 → 22，−59%），而不是"应该能减不少"
3. **加了预算守卫 + 回滚开关**——前者防回弹，后者让"敢撤"

**一句话**：机制用签名清单 + core 注册表双来源，入口用命令面板收拢，
约束用预算守卫锁住，风险用回滚开关兜底。
