> 版本：方案稿 v0（2026-10-31 · 针对 v25.5.0 现状）
> 状态：**只写方案，不动代码**。落地时按「docs/109 开发规则」逐批次本地 commit → 发布链路上远端。
> 说明：文中代码片段为**方案级示意**（帮助理解要改什么、怎么改），落地时需按当前源码核对具体函数签名与行号；改 `modules/installed/` 后还要走重签三步（`rebuild_modules_repo.py --apply` → `sign_modules.py` → `check_repo_sync.py`）。

| 组 | 功能 |
|---|---|
| A 对话交互 | 发送、附件、设置、命令面板、首次向导/教程 |

| F 插件运行时 | 插件运行时(43 个模块) |

每条功能统一用「现状 → 深化方向 → 详细步骤 → 改动位置 → 具体代码改动」五段展开。

## A 组：对话交互

### A1. 发送（send）

**现状**：`core/feature_registry.py` 入门 `send`，主窗口按钮走 `send()`；输入只有即时发送，无草稿保留、无发送历史。

**深化方向**：三次保险 ——「自动存草稿 → 发送历史可回退 → 智能发送时机」。

**详细步骤**
1. 输入框内容变化时（QTextEdit `textChanged`）防抖 1.5s，把草稿写入 `data/drafts/{会话id}.json`。
2. 启动/切换会话时若存在草稿，提示「恢复上次未发送内容？」。
3. 记录最近 50 条已发送文本到 `data/input_history.json`，`Ctrl+↑/↓` 在输入框回滚。
4. 长文 + 生成中时，发送按钮状态提示（如「正在生成，再按=强制插入」）。

**改动位置**
- `gui/mixins/chat_mixin.py`（发送入口 `send()` 所在）
- 新增 `core/draft_store.py`（草稿/历史读写，走 `core/safe.py` 原子写）
- `gui/chat_input_ext.py`（输入框扩展，已有拖文件/粘贴截图）

**具体代码改动（示意）**

### A2. 附件（attach）

**现状**：拖文件/粘贴截图已做（`gui/chat_input_ext.py`），OCR 兜底已做（O1）。但只覆盖静态图片/文档，无音视频、无大文件分片。

**深化方向**：从「文件上传」升级为「内容理解」——音视频转写、大文件流式、图片直接多模态问答。

**详细步骤**
1. 音频/视频附件先走本地 ASR/抽帧（`modules/installed/whisper` 已是可选组件），产出文字底稿再进上下文。
2. 超过阈值（如 20MB）的文件走分片 + 断点，避免一次性塞内存；用哈希校验。
3. 图片附件默认触发多模态提问（VLM），而不是只 OCR。
4. 附件类型决定「工具提示」：图片→视觉工具、PDF→document_parser、代码→工作台。

**改动位置**
- `gui/chat_input_ext.py`（附件处理、类型分发）
- 新增 `core/attachment_pipeline.py`（音视频转写/分片/类型路由，薄模块，走 `trunk.call`）
- `core/context_builder.py` 的 `_TOOL_HINTS`（附件类型加提示）

**具体代码改动（示意）**

4. 检索结果做「引用置信度」排序（命中段落 + rerank 分）。

**改动位置**
- `core/rag_pipeline.py`（查询改写、失效降权）
- `core/retrieval.py`（返回带 `offset` 的段落标识）

## 落地建议（整体）

1. **分批原则**（沿用入口治理经验）：按「P 值 × 依赖」排期，每批独立本地 commit → 全量门禁 → 发布链路（`tools/github_api_push.py`）。
2. **建议批次顺序**（依赖少的先做，见效快的先做）：
   - 批 1（交互体验，低风险）：A1 发送、A4 命令面板、D2 日志、D6 反馈。
   - 批 2（任务/资料纵深）：B1 任务编排、B2 知识库溯源、B3 记忆、B4 深度研究。
   - 批 3（代码 Agent 纵深）：C1 工作台。
   - 批 4（生态/可观测）：D1 插件市场、D3 Trace、D4 自检、D5 星图。
   - 批 5（核心链路 & 运行时）：E1 工具选择、E2 人格、F1 插件运行时。
3. **每批验收**：`py -3 tools/pre_commit_check.py --full` 全绿 + 对应 `tests/` 定向通过 + 文件长度守卫不破。
4. **本次方案先不动代码**：当确认要开始某批时，再按本方案逐批拆成「每批详细步骤 + 改动文件清单」落地（与上次入口治理流程一致）。
