## 0. 一页结论

小6 现在“能做的事”已经不少：对话人格提示、向量/情景记忆、群聊角色、反思打分、代码 Agent（探索 → patch → 测试 → 回修）、电脑 Agent、工作台 IDE、命令中心、终端、补全。但**做深**的瓶颈不在功能数量，而在三处“粗粒度”：

1. **对话理解靠关键词和固定提示**：`is_simple` 用长度+词表判断（`core/pipeline/context_builder.py:27`），人格是 500 字规则拼接（`core/personality_style_hints.py:157`），记忆只回填 2~3 条、每条截 100 字（`context_builder.py:133`、`modules/installed/memory_loop.py:113`）。因此“拟人”容易变成“按规则演”，长对话会漂、会重复、会答非所问。
2. **工作台自然语言只有两套硬编码解析**：统一入口是关键词打分路由（`core/agent_router.py:42`），电脑操作是 220 行正则（`core/computer_command_parser.py:40`），命令中心只是“精确/子串匹配 + 文件名兜底”（`gui/ide_sidebar.py:568`），没有槽位、澄清、多步计划与撤销。
3. **代码准确度受限于“关键词检索 + 整文件替换”**：上下文按词频挑 22 个文件、24k 字符（`core/code_context.py:90`），补全只有关键字+本文件符号（`gui/code_editor_widget.py:125`），AI 修复直接整文件覆盖（`gui/code_editor_ai.py:91`），没有 LSP、跨文件语义索引、影响面测试选择与失败定位。

**路线**：先用一个批次补“评测底座”（否则做深无法证明有效），再按“对话 → 记忆 → 工作台 NL → 代码索引 → 代码 Agent → 补全 → 成长/主动性 → 整合发版”推进，共 9 个批次（41–49），约 50–60 人日。每批都带开关、可回滚、带量化验收，且保持现有守卫（单文件 ≤600 行、按钮 ≤60、Feature/模块计数、silent 0、线程规则）全绿。

**预期收益**（以批次 41 建立的基线为准做验收）：
- 对话拟人度人工评分 ≥4.0/5，人格一致性探针 ≥90%，重复率 <5%，短问短答符合率 ≥95%
- 工作台 NL 意图准确率 ≥92%，破坏性操作误执行 0，澄清后完成率 ≥90%
- 代码任务 pass@1 相对基线 +20 个百分点，平均回修轮次 <2，无关文件改动率 <10%，回归率 <3%

## 2. 目标与度量体系

### 2.1 产品目标（按优先级）

1. **像人**：不是“演人格”，而是理解情绪/关系/场景后，用稳定的说话方式回应；长对话不漂移、不重复、不机械。
2. **听得懂**：工作台里一句话能变成“明确意图 + 参数 + 可确认的计划”，含糊时会问一句，破坏性操作绝不猜。
3. **改得准**：代码任务能定位到正确文件/符号/测试，改动尽量小，验证尽量准，失败能解释。
4. **可证明**：每个目标都有离线基准、线上指标和回归门禁，不靠“感觉变好了”。

### 2.2 指标树（每个指标都要写清口径）

| 层级 | 指标 | 口径 | 目标（批次 49 前） |
|---|---|---|---|
| 聊天 | 拟人度 | 5 维 rubric（自然/共情/一致/有趣/不冒犯），人工 1–5 分 | ≥4.0 |
| 聊天 | 人格一致性 | 100 条探针（价值观/称呼/长度/边界）符合率 | ≥90% |
| 聊天 | 重复率 | 近 20 轮 4-gram 重复 + 固定句式命中率 | <5% |
| 聊天 | 短问短答符合率 | 用户 ≤8 字时回复 ≤2 句且不扩写 | ≥95% |
| 聊天 | 记忆命中率 | 需回忆的 100 条问题中正确引用率 | ≥85% |

| 聊天 | 首 token | P50 / P95（云/本地分开统计） | 云 ≤1.5s / 本地 ≤3s |
| 工作台 NL | 意图准确率 | 200 条标注语句，intent 完全正确 | ≥92% |

| 工程 | 性能 | 启动、首屏、内存、包体 | 不劣化 >10% |

### 2.3 基线建立方法（批次 41）

- 聊天：300 轮 golden set（10 类 × 30），每类含期望“行为特征”而非固定答案；用当前版本跑 3 次，人工标注 200 条用于校准 LLM 评审。
- 代码：从仓库历史中挑 40 个“真实修复/小功能”提交，构造“回退到修复前 + 跑测试”的离线任务；记录当前 pass@1、轮次、diff 大小、耗时。
- NL：200 条工作台语句（文件/搜索/Git/运行/终端/Agent/设置），标注 intent 与槽位；记录当前路由/命令中心表现。
- 所有基线写入 `docs/92` 的新章节，并固定随机种子与模型版本，保证可复现。

## 3. 聊天拟人智能（做深）

### 3.1 从“关键词理解”升级为“结构化对话状态”

**现状问题**
- `is_simple` 只看长度和词表（`context_builder.py:27`），导致“今天好累”被当简单句，不注入人格/记忆；而“帮我看看这个报错”可能被当复杂句，白跑检索。
- 路由/工具/联网全部靠词表，跨轮意图（“那再改一下”“就按刚才说的”）无法识别。

**方案**
1. 新增 `core/pipeline/intent_state.py`（预计 ≤300 行）：一次结构化输出，字段固定：
   ```json
   {
     "intent": "seek_comfort|chat|ask_fact|task|code|computer|meta",
     "emotion": {"label": "低落", "intensity": 0.7},
     "relation_move": "self_disclose|tease|check_in|none",
     "answer_shape": {"length": "short|medium|long", "ask_back": false, "tone": "soft"},
     "memory": {"need": true, "query": "工作 压力"},
     "tools": ["web_search"],
     "confidence": 0.82
   }
   ```
2. 执行顺序：**小模型/规则快路径 → 置信度不足才调云端结构化**；本地模型不可用时退回现有词表（保持兼容）。所有字段做 schema 校验，缺字段按默认值。
3. 只把 `intent_state` 用于“选上下文/选长度/选是否追问”，**不直接把内部标签写进回复**，避免“我在共情你”这种出戏。
4. 灰度：`ai.intent_v2` 开关，先 shadow（只记录不生效）一周，对比旧 `is_simple` 的误判率，再切主路径。

**验收**：300 轮 golden set 上，意图分类准确率 ≥90%；“该短则短”符合率 ≥95%；检索触发次数下降 ≥20% 且回答质量不降。

### 3.2 “先想后说”：回应规划层

**现状问题**：人格提示把“情绪/称呼/长度/安慰/吐槽”一次性塞进 500 字，模型只能同时满足十几条规则，结果要么机械、要么顾此失彼。

**方案**
1. 新增 `core/persona/planner.py`：在生成前产出一个**不展示给用户**的回应计划：
   - `move`：共情 / 给建议 / 轻调侃 / 追问 / 拒绝 / 纯陪伴
   - `length`：1 句 / 2–3 句 / 分段
   - `stance`：站用户 / 中立分析 / 明确反对
   - `callback`：是否引用某条记忆（由记忆层给候选）
   - `taboo`：本轮不碰的话题（隐私、旧伤、比较）
2. 生成时只给模型“计划 + 3 条以内风格示例”，不再堆 22 条宪法；宪法留在系统层做**离线一致性检查**，不参与每轮 token 竞争。
3. 计划层可解释：调试面板显示“为什么这轮短/为什么追问”，便于定位“突然不像人”。

**验收**：人工 pairwise 对比旧版，胜率 ≥60%；平均回复长度标准差下降；短问短答符合率 ≥95%。

### 3.3 表达层：去模板、去 AI 腔、保人味

**现状问题**
- 固定 few-shot 5 条（`personality_style_hints.py:144-155`）长期不变，模型会模仿成固定腔调。
- `short_reply_hint`、`repeat_hint` 是规则触发，容易“为了短而短”“为了吐槽而吐槽”。
- 没有生成后的自检，重复、列表化、客服腔无法拦截。

**方案**
1. **情境化示例检索**：从“高质量对话库”（人工挑 200–300 条 + 用户点赞回复）按场景/情绪/关系阶段检索 2–3 条，替换固定 few-shot；示例带来源与评分，低分不进。
2. **反模板约束**：维护 `config/persona_banned.json`（客服腔、鸡汤句、过度排比、“作为一个AI”等），生成后命中则重写；同时做 4-gram 重复惩罚。
3. **两次生成 + 重排**（仅复杂轮）：候选 A（更短更自然）/ B（更完整），用一致性+拟人 rubric 选一个；简单轮只生成一次，控延迟。
4. **标点/表情策略**：按关系阶段与场景控制感叹号、省略号、emoji；不强制“每句都带表情”。
5. **口吻一致性**：把“用户偏好”（称呼、语速、是否用表情）沉淀为画像，而不是每轮临时提示。

**验收**：重复率 <5%；禁用句式命中 <1%；人工“像人”评分 ≥4.0；不同场景下语气差异可感知（盲测能区分安慰/调侃/工作模式）。

### 3.4 情绪与关系：从“14 种心情”到连续状态

**现状问题**：`personality_state.update_emotion` 是事件+规则表；情绪是离散标签，缺少强度、衰减、关系阶段，长对话容易“上一轮生气下一轮没事”。

**方案**
1. 状态向量：`valence`（-1..1）、`arousal`（0..1）、`energy`、`trust`、`intimacy`；每轮按“事件评估（OCC 简化版）+ 衰减半衰期”更新，落盘 `data/persona_state_v2.json`（与旧文件并存，迁移脚本一次性转换）。
2. 事件评估：用户夸奖/批评/失约/久别/深夜/连续追问 → 对状态的影响系数可配置；避免“一句夸就亲密”。
3. 关系阶段：陌生 → 熟悉 → 亲近 → 默契，用互动次数、连续天数、自我披露深度、冲突修复综合判定；阶段只影响称呼/主动频率/玩笑边界。
4. 冲突修复：检测到用户不满时，先承认→解释→给选择，不急着撒娇；修复成功才回涨信任。
5. 防“情绪表演”：回复计划里情绪强度低于阈值就不表达，避免每轮都“哎呀”。

**验收**：20 段多轮剧本（安慰/冲突/久别/玩笑）人工评估情绪连贯性 ≥4/5；状态与文本情绪不一致率 <10%。

### 3.5 记忆 v2：该记的记、该取的取、冲突能消

**现状问题**
- 写入：每轮都 `mem_add`，无重要性判断；情景只截 80/120 字。
- 检索：向量 top 3 + 情景 2 条，每条 100 字；无混合检索、无重排、无去重。
- 冲突：新旧事实冲突时不处理；用户纠正后仍可能被旧记忆带偏。
- 画像：没有结构化“用户是谁/偏好/承诺/禁忌”。

**方案**
1. **记忆卡片 schema**（`data/memory_cards_v2.json`，带版本号）：
   ```json
   {
     "id": "m_20261029_001",
     "type": "fact|preference|commitment|event|relation",
     "subject": "用户", "predicate": "不喜欢", "object": "被催",
     "confidence": 0.86, "importance": 0.7,
     "source_turn": "conv_123#t8", "created_at": "...", "last_used": "...",
     "expires_at": null, "privacy": "normal|sensitive"
   }
   ```
2. **写入策略**：规则先筛（姓名/计划/承诺/喜好/禁忌/明确纠正），再让 LLM 判重要性（0–1）；低于阈值只留原始对话，不进卡片；敏感信息默认不落卡。
3. **混合检索**：`score = 0.45*cos + 0.25*BM25(FTS5) + 0.15*recency + 0.15*importance`；MMR 去重；top 5–8 条、每条 200–400 字；按“事实/偏好/承诺”分槽注入，而不是一坨文本。
4. **冲突消解**：同主语+谓语的新事实优先；用户明确纠正 → 旧卡降置信并标记 `superseded_by`；每月 consolidation 合并重复、补全时间线。
5. **画像视图**：设置页只读展示“小6 记得的你”（可编辑/删除/导出），让用户能纠正，避免“黑箱记忆”。
6. **遗忘**：重要度加权衰减（承诺/禁忌不衰减；寒暄 30 天衰减）；保留“被引用次数”作为强化信号。

**验收**：100 条回忆问题命中率 ≥85%；冲突问题正确率 ≥90%；注入 token 下降 20%（更少但更准）；用户纠正后 1 轮内生效。

### 3.6 反思与长期成长：从“打分”到“可验证改进”

**现状问题**：`self_reflect` 只给 1–10 分 + 一句建议，截断 100/200 字，50 条上限；低分建议直接塞回 prompt，没有验证是否真的改好。

**方案**
1. **多维 rubric**：相关性 / 拟人 / 共情 / 有用 / 安全（各 1–5），总分不再用单一 10 分；低分必须给“可执行改写建议”。
2. **失败用例库**：低分轮自动进入 `tests/eval/chat_failures.jsonl`（脱敏），批次回归时重跑；修复后标记 resolved。
3. **建议晋升机制**：同一类建议出现 ≥3 次才晋升为“人格规则/反模板词”，避免一次偶发就改人格。
4. **周报**：成长报告从“聊了多少”改为“本周学会了什么/哪类问题还弱/下周改什么”，并附证据。
5. **防过拟合**：反思建议有 TTL（30 天），到期重新评估；避免长期堆叠成“补丁人格”。

**验收**：低分复现率下降 ≥50%；建议晋升后同类问题人工评分提升 ≥0.5；prompt 中反思建议 token 不超过 120。

### 3.7 主动性与多模态（后置，不抢主线）

- 主动搭话：从“一天最多一次”升级为“事件驱动”（久别、用户情绪低、承诺到期、任务完成），有预算与免打扰时段；先小范围灰度。
- 语音：复用现有 speech/edge-tts 能力，先做“语气跟随情绪”（语速/停顿），再做打断与附和；不在第一批做唇形/虚拟人。
- 视觉：截图/摄像头输入先接“看屏幕回答”，再做“看图改代码”；隐私默认本地处理。

**验收**：主动消息接受率 ≥60%、关闭率 <10%；语音首包 ≤1.5s；视觉问答引用屏幕内容准确率 ≥85%。

## 4. 工作台自然语言（做深）

### 4.1 统一意图 schema + 混合路由

**现状问题**：`agent_router` 只有三域词表；`computer_command_parser` 是长正则；命令中心是字符串匹配。三者互不复用，新增说法就要加词/加正则，越加越脆。

**方案**
1. 新增 `core/nl/intents.py`（意图注册表），每个意图声明：
   ```python
   {
     "name": "file.rename",
     "domain": "workspace",
     "slots": {"from": "path", "to": "path"},
     "examples": ["把 a.py 改名为 b.py", "重命名这个文件为 b.py"],
     "risk": "medium",
     "undo": True,
     "handler": "workspace.rename"
   }
   ```
   首批覆盖 30 个高频意图：打开/新建/保存/另存/重命名/删除/搜索/全局搜索/替换/跳转行/运行/调试/终端命令/Git 暂存/提交/分支/撤销/重做/格式化/解释代码/修复选区/AI 任务/设置项/插件/主题/分屏/关闭页签。
2. **三段式路由**：
   - 快路径：现有正则/精确命令（0 成本，覆盖 60% 高频）
   - 结构化分类：小模型输出 `{intent, slots, confidence}`（JSON schema 约束）
   - 兜底：置信度 <0.7 或槽位缺失 → **澄清**（“你是想改文件名，还是移动位置？”），绝不猜破坏性动作
3. 路由结果统一成 `Action` 对象，交给现有 `AgentOrchestrator`/工作台命令执行器；旧入口保留，逐步迁移。
4. 所有动作记录 `action_id`，进入撤销栈（文件类用备份/反向 patch；Git 类用 reflog 提示；终端类不可撤销则事先确认）。

**验收**：200 条 NL 基准意图 ≥92%、槽位 F1 ≥0.90；破坏性误执行 0；旧命令中心行为不回归。

### 4.2 实体解析：文件、符号、分支、命令

**现状问题**：`find_file` 只按名字模糊找；代码符号没有跨文件解析；分支/命令没有候选与消歧。

**方案**
1. 实体来源：`WorkspaceIndex`（文件/符号）、Git（分支/提交）、命令注册表（终端/任务）、设置项（配置键）。
2. 解析顺序：精确路径 → 当前打开文件相对 → 索引模糊（编辑距离 + 最近使用 + 同目录优先）→ 多候选弹选择（键盘可选）。
3. 指代消解：“这个文件/这里/刚才那个” → 当前编辑器/选区/最近操作对象；多轮任务保留 `focus` 栈。
4. 槽位类型校验：路径必须存在（创建类除外）、行号范围、分支名合法、命令白名单；不合法就澄清而不是执行。

**验收**：指代类语句（“把这个改名”“刚才那个函数”）解析成功率 ≥90%；错误路径执行 0。

### 4.3 多步计划、预览与撤销

**现状问题**：工作台只支持单动作；代码 Agent 有 plan 但 NL 命令没有；用户说完“整理一下项目”无法预期会发生什么。

**方案**
1. 复杂语句先出**计划卡**（3–6 步，每步 intent + 目标对象 + 风险），可勾选/改顺序/取消；确认后逐步执行，每步可暂停。
2. 每步执行前对高风险动作给 diff/命令预览（复用现有 patch 预览与命令预览）。
3. 撤销：文件改动走备份 manifest；多步任务支持“撤销整个任务”（逆序回滚）；不可逆动作（推送、删除分支）单独二次确认。
4. 失败处理：某步失败 → 停止后续、展示已完成/未完成、给“重试该步/跳过/回滚”三个选项。

**验收**：多步任务完成率 ≥85%；撤销成功率 100%；用户对“执行前知道要做什么”的评分 ≥4/5。

### 4.4 命令中心升级（最小改动、最大感知）

**现状问题**：`_run_command` 只做精确/子串/文件名兜底（`gui/ide_sidebar.py:568`），没有排序、参数、预览、最近使用。

**方案**
1. 输入即 NL：先走 4.1 路由；无法确定时回退到“命令/文件模糊搜索”，结果按 最近使用 + 匹配度 + 当前上下文 排序。
2. 支持参数：选中命令后展示槽位表单（文件选择器/分支列表/行号），而不是弹裸输入框。
3. 结果预览：右侧显示“将执行什么/影响哪些文件”，危险动作红色标识。
4. 历史与收藏：最近 20 条、固定收藏、`Ctrl+Shift+P` 直接复现。

**验收**：命令中心任务完成时间下降 ≥30%；“找不到命令”反馈率 <5%；不新增按钮（沿用动作链接/列表）。

### 4.5 工作台对话的上下文感知

**现状问题**：AI 面板默认把整段目标交给代码 Agent；编辑器“AI 修复”把整文件+输出发过去；没有自动带“当前文件/选区/诊断/diff”。

**方案**
1. 默认上下文包：当前文件路径 + 选区（若有）+ 光标附近 40 行 + 当前诊断（ruff/ast）+ 未提交 diff 摘要 + 相关测试。
2. 用户显式说“整个项目”才升级到仓库级检索；否则默认局部，降低延迟与误改。
3. “解释/重构/修复/写测试”四个高频动作做成快捷意图（选中代码后出现动作链接，不新增按钮）。
4. 对话里展示“我用了哪些上下文”（可折叠），让用户可纠正“不是这个文件”。

**验收**：选区任务正确文件命中率 ≥95%；无关文件改动 <10%；上下文 token 下降 ≥30%。

## 5. 代码准确度（做深）

### 5.1 代码索引 v2：从“词频”到“语义 + 图 + 类型”

**现状问题**：`code_context` 用目标词在文本/符号里打分；没有函数级语义、调用关系、类型信息；`related_tests` 只按文件名/目录猜。

**方案**
1. **函数级 chunk**：按 AST/tree-sitter 切函数/类/方法，chunk 含签名、docstring、前后 5 行、文件路径、符号 id；嵌入走本地模型（复用 `vector_store` 的 Ollama 通道，批量、缓存、失败降级）。
2. **代码图**：imports（已有 `imports_of`）、被引用、调用（AST 近似）、继承、测试映射（测试文件 → 被测符号）；落 SQLite，增量更新（文件 mtime+hash）。
3. **LSP 可选桥**：优先接 `jedi-language-server`（Python）与 `pyright`（TS/JS），拿 definition/references/type/diagnostics；未安装时退回 AST 索引（不阻塞）。
4. **混合检索**：`0.5*语义 + 0.3*BM25 + 0.2*图邻近`；MMR 去重；按“目标函数 → 同文件上下文 → 直接依赖 → 测试”排序。
5. **索引预算**：单仓库 ≤2 万文件；排除 `dist/build/data/.venv`；首次建索引后台执行，UI 显示进度。

**验收**：代码问答引用准确率 ≥90%；“这个函数在哪被调用”召回 ≥85%；索引构建 1 万文件 ≤60 秒（增量 ≤2 秒）。

### 5.2 上下文工程 v2：少而准

**现状问题**：22 文件/24k 字符一刀切；本地 8k 上下文时会被截断；失败重试时只带错误摘要，缺少“失败栈对应文件”。

**方案**
1. 预算感知：按模型能力（8k/32k/128k）分配 `system / 任务 / 代码 / 测试输出 / 历史` 配额；超限先压缩“远邻文件”为签名+docstring。
2. 必带集合：目标符号定义、直接调用方/被调用方、相关测试、失败栈帧文件、最近 diff。
3. 失败回修：解析 traceback → `file:line` → 只注入该函数及测试；错误指纹（已有）用于去重。
4. 摘要缓存：同一文件多次读取用增量摘要；仓库地图分两级（目录级/模块级）。
5. 上下文可解释：调试面板列出“选了哪些文件/为什么”，便于评估与调参。

**验收**：同等 token 下 pass@1 提升 ≥10pp；上下文 token 下降 ≥25%；失败定位到正确文件 ≥80%。

### 5.3 补丁协议：从“整文件”到“局部编辑”

**现状问题**：`ai_fix` 要求模型返回完整代码并整体替换（`gui/code_editor_ai.py:91-123`），大文件必炸；`code_agent` 的 patch 虽支持 update，但模型常给整文件内容，diff 巨大。

**方案**
1. 新 patch 协议（兼容旧格式）：
   ```json
   {"files":[{"path":"gui/x.py","edits":[
     {"find":"...唯一片段...","replace":"...","occurrence":1}
   ]}],"reason":"..."}
   ```
   应用前校验：片段唯一、base hash 一致、应用后语法可解析；失败让模型重试“更小的片段”。
2. 编辑器 AI 修复改为“选区/函数级 patch + diff 预览 + 逐块接受”，不再整文件覆盖。
3. 最小性检查：改动行数/文件数超阈值（如 >120 行或 >5 文件）要求拆分或二次确认。
4. 生成前先给“修改计划”（改哪些文件/为什么），复杂任务默认走 plan 审批（已有 `code_plan`）。

**验收**：平均 diff 行数下降 ≥40%；大文件（>1000 行）修复成功率 ≥80%；无关改动 <10%。

### 5.4 测试闭环：跑得准、定位快、可回滚

**现状问题**：每轮跑全部探测到的测试/lint；失败只取摘要；没有影响面选择、flake 处理、超时策略。

**方案**
1. **影响面测试选择**：代码图给出“改动符号 → 直接/间接测试”，先跑命中集，再跑全量（时间允许时）。
2. **失败定位**：解析 pytest/unittest/npm 输出 → 文件:行 → 失败测试名 → 关联符号；回修 prompt 只带这些。
3. **flake 隔离**：同一测试连续两次“失败→通过”标记 flaky，本轮不阻塞，但记录；全量门禁仍严格。
4. **预算**：单轮测试 ≤180 秒、总任务 ≤10 分钟；超时先缩到命中集，仍超时则报告“未验证”而不是假装成功。
5. **回滚**：沿用现有 backup manifest；失败/取消自动回滚到任务前（用户可选保留）。

**验收**：平均验证时间下降 ≥35%；失败定位准确率 ≥80%；flaky 误判导致的失败 <5%；回滚成功率 100%。

### 5.5 双角色评审与自检

**现状**：已有 `explore_project → modify_with_report` 双角色（`core/code_roles.py`），但触发依赖配置，评审维度不固定。

**方案**
1. 固定“探索者/修改者/评审者”三角色：评审者只看 diff + 测试 + 目标，输出 `通过/需修改/拒绝` 与理由；不通过则带理由回修一轮。
2. 评审 rubric：目标达成、最小改动、风格一致、测试覆盖、安全边界；任一项红则拒绝。
3. 评审结果进入任务报告（用户可见“为什么这样改”）。

**验收**：评审拦截的真实问题 ≥50%；评审增加的耗时 ≤15%；用户对改动可解释性评分 ≥4/5。

### 5.6 补全与代码问答

**现状问题**：补全只有关键字+本文件符号（`gui/code_editor_widget.py:125`）；没有类型、跨文件、排序；代码问答没有引用。

**方案**
1. 补全 v2：LSP（若可用）→ 索引符号（跨文件）→ 本文件 → 关键字；按上下文类型/最近使用排序；300ms 防抖保留。
2. 可选 FIM（fill-in-middle）：本地小模型按前后文生成 1–3 行，默认关闭、隐私模式不启用。
3. 代码问答：回答必须带 `file:line` 引用；检索不到就说“没找到”，不编造；支持“解释/找定义/找引用/影响面/写测试”五种模板。
4. 结果可操作：问答里的文件/符号可点击跳转；“生成测试”直接进入 patch 预览。

**验收**：补全采纳率提升 ≥20%；跨文件符号补全 Top-5 命中 ≥80%；问答引用准确率 ≥90%。

### 5.7 内部代码基准（必须可重复）

- 40 题来源：仓库历史真实修复（回退构造）+ 20 题合成小任务（新增函数/修 bug/补测试/重构）。
- 每题包含：初始仓库快照、目标描述、隐藏测试、允许改动范围、超时。
- 指标：pass@1、轮次、diff 行数、无关文件数、测试时间、token 成本。
- 运行方式：离线沙盒、固定模型与温度、随机种子；结果写 `docs/92` 与 `data/eval_code.json`。
- 门禁：合并前跑 10 题 smoke（≤8 分钟）；每周跑全量 40 题。

> 约束：单文件 600 行硬上限；模块数会触发 `check_feature_freeze`，每批新增需按既有先例 `--rebase --force` 并在 `docs/20` 记录理由；尽量把逻辑放进现有模块的 mixin（如 `CodeContextMixin`、`CodeExplorerMixin`），减少新文件。

### 6.2 开关与灰度

所有新能力挂 `config` 开关（默认关 → shadow → 10% → 全量）：
```json
{
  "ai": {"intent_v2": false, "persona_planner": false, "memory_v2": false},
  "nl": {"router_v2": false, "undo": false},
  "code": {"index_v2": false, "local_patch": false, "lsp": false, "test_select": false}
}
```
- shadow 模式只记录“新方案会怎么做”，不影响现有回复/执行。
- 每批上线前跑 A/B（同题集、同模型），不达标不切默认。
- 任何新链路必须有超时与降级：意图分类失败 → 词表；索引失败 → 仓库地图；LSP 失败 → AST；记忆检索失败 → 最近对话。

### 6.3 数据与迁移

- `persona_state_v2.json`、`memory_cards_v2.json`：带 `schema_version`，启动时迁移旧数据并备份到 `data/backups/`。
- 迁移必须可回滚（保留旧文件，不原地覆盖）；迁移失败自动回旧版，不阻塞启动。
- 评测数据（golden/failures）脱敏，不含真实姓名、路径、密钥；只存特征与标签。

### 6.4 性能预算

| 场景 | 预算 |
|---|---|
| 意图分类（本地） | ≤300ms P95；云端 ≤1.2s |
| 检索（聊天） | ≤1.2s P95（失败降级） |
| 记忆写入（后台） | 不阻塞回复；单轮 ≤200ms |
| 代码索引（增量） | ≤2s/文件批；首次后台 |
| 代码上下文构建 | ≤3s；token 按模型配额 |
| 单轮代码测试 | ≤180s；总任务 ≤10min |
| UI 线程 | 不新增阻塞调用；沿用现有线程守卫 |

## 8. 成本、隐私与安全

- **成本**：意图分类/评审/重排优先本地；云端只用于“难例”与结构化输出；每次调用记录 token 与用途，设日预算。
- **隐私**：记忆、画像、评测数据本地存储；云端请求前脱敏（复用现有 redaction）；敏感记忆不落卡；提供导出/删除/关闭记忆。
- **安全**：NL 破坏性动作强制预览+确认；命令白名单/沙箱沿用现有 `command_policy`；代码 Agent 不改工作区外文件；提示注入内容按不可信资料包裹（已有 `wrap_search_result`）。
- **边界**：不生成攻击他人/恶意软件内容；拟人化不等于“假装真人”，被问身份时明确是 AI（保留现有宪法第 12 条）。

## 9. 风险与“不做”清单

| 风险 | 应对 |
|---|---|
| 评测过拟合/自评自夸 | 人工校准 200 条、盲测 pairwise、固定外部题集、每季度换题 |
| 拟人化变成“油腻/表演” | 情绪强度阈值、反模板、用户可调“话少/话多” |
| 延迟上升 | 分项预算、并行、缓存、影子先跑、复杂轮才双生成 |
| 本地 8k 上下文 | 预算感知、签名摘要、云端难例路由 |
| 记忆错误/隐私 | 用户可见可改、敏感不落卡、冲突消解、导出删除 |
| NL 误执行 | 高风险预览+确认、撤销栈、破坏性 0 容忍 |
| 代码 Agent 改坏 | 备份/回滚、最小补丁、测试门禁、评审者 |
| 模型/供应商变化 | 能力矩阵 + 降级链 + 基准回归 |
| 模块/按钮膨胀 | 复用 mixin、动作链接替代按钮、每批 freeze 记账 |

**不做（本阶段）**：
- 不做大规模本地微调/RLHF（先靠结构化状态+检索+评测；数据与算力成本不划算）
- 不做全自动后台改代码（必须有人确认/可撤销）
- 不做“无上限长期记忆”（必须有重要度、衰减、冲突消解）
- 不做“每轮都多模型投票”（成本/延迟不可接受，只难例升级）

## 10. 立刻可做的 10 个 Quick Wins（低风险、不等大改造）

1. **编辑器 AI 修复不再整文件覆盖**：先做“选中/当前函数 → diff 预览”，复用现有 `_preview_ai_change`。
2. **命令中心加自然语言兜底**：无法精确匹配时，用现有意图词表给 3 个候选，而不是直接“未找到”。
3. **记忆注入扩容**：向量 top_k 3→5、单条 100→300 字，先观察 token/质量（不改 schema）。
4. **短问短答后置校验**：用户 ≤8 字而回复 >3 句时，自动压缩/重写（规则+一次小模型调用）。
5. **路由置信度阈值**：`agent_router` 置信度 <0.45 时先问一句“是要改代码还是操作电脑？”，不直接回聊天。
6. **补全接工作区符号**：用 `WorkspaceIndex.find_symbols` 补跨文件候选（不改 LSP）。
7. **失败回修带栈帧文件**：`code_agent` 的 `last_error` 里解析 `file:line`，下一轮只注入该文件/函数。
8. **反模板黑名单**：先收 30 条“AI 腔/客服腔”，生成后命中即重写。
9. **反思改 4 维 rubric**：相关性/拟人/有用/安全，低分进失败库（不改存储上限）。
10. **埋点**：记录首 token、总耗时、检索命中、用户纠正、撤销次数，为批次 41 基线供数。
