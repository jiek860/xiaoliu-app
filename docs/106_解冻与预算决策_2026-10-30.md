## 1. 为什么解冻

冻结期的目标是「10 条主链路做到 90 分、不再加新模块」。现状核查发现三类问题：

1. **能力已实现但用户不可达**：48 批的失败库 / 建议晋升 / 周报 / 主动搭话统计全部只在逻辑层，
   `gui/` 零引用，`data/chat_failures.jsonl` 等数据文件从未生成——闭环断在最后一步。
2. **信号声明了却没接线**：`tools/audit_signals.py` 审计出 `problemsChanged`（编辑器问题列表）
   与 `InlineDiffView.applyRequested/undoRequested` 没有任何 `connect`。
3. **聊天输入与工作台诊断有明确体验缺口**：拖入文件不解析、粘贴图片不支持、按住说话没做、
   工作台问题不实时、跑测试只能跑当前文件。

继续冻结只能修 Bug，上面三类都做不了，因此按既定流程解除冻结，并保留棘轮守卫。

## 4. 增长纪律（避免解冻后失控）

1. 每批最多新增 **2 个** Feature id；超过必须删旧或走评审。
2. 按钮只允许「一进一出」或本文件列明的 4 个；新增后执行
   `py -3 tools/check_buttons.py --rebase` 并把理由写进提交说明。
3. 新文件必须 <600 行；`code_editor_dialog.py`（599 行）**只许降**，先拆后改。
4. 新增异常分支一律走 `core.diagnostics.swallowed`，不得新增裸 `except`。
5. 新增模块必须附纯函数测试，保证改动行覆盖率 ≥70%。

## 5. 回滚办法

1. 把 `tools/freeze_baseline.json` 的 `active` 改回 `true`，守卫立即恢复。
2. `git revert` 对应批次提交；文档保留（决策记录不删）。
3. 按钮预算回滚：`py -3 tools/check_buttons.py --rebase`（仅在删按钮后）。
4. 数据文件（失败库/候选/晋升）由新面板写入，回滚代码不影响已生成数据。

## 6. 收尾

M4 完成后执行 `py -3 tools/check_feature_freeze.py --init --force` 重新建立基线

### 7.2 真实接线（用户要求「所有没连上的信号都连上」）

| 之前断点 | 现在 |
|---|---|
| `CodeEditWidget.problemsChanged` 无 connect | `ProblemsHub` 注册全部标签，节流 250ms 刷新底部「问题」并聚合状态栏 |
| `InlineDiffView.applyRequested/undoRequested` 无 connect | 应用/撤销后 `QTimer.singleShot(0, reload)` 刷新打开的标签 |
| 拖文件只记 `_dropped_file`，不解析 | `drop` 事件 → `document_parser.parse` → 内容进输入框 |
| `upload_file` 只 `open().read()`，PDF/Word 报编码错 | 统一走 `chat_input_ext.attach_document` |
| 语音只能固定录 5 秒 | `voice.listen(stop_event=...)` + 按住说话（松开即停，最长 20s） |
| 工作台没有测试入口 | 底部「测试」页（受影响测试 / 运行全部 / 只重跑失败） |
| 运行结束只有「退出码: 1」 | `run_parse.summary` + `error_hints`（📌 结论 / 💡 下一步） |
| 文件树无过滤 | 资源管理器顶部筛选框（`setNameFilters`，不换模型） |
| AI 面板拿不到当前代码 | Ctrl+Shift+A / 标签右键「发送到 AI（含选区）」 |
