## 一、P0：插件仓库滞后（先做，约 15 分钟）

### 现状（实测）

- `E:\xiaoliu\modules_repo` 有 **2 个未提交文件**：`hot_reload.py`（+25 行）、`manifest.json`（size/signature 变化）。
- 内容：热重载"选类规则"修复——跳过 `_` 开头的私有类，并优先选 `BaseModule` 子类。原实现取模块里第一个类，而 `voice.py` 的第一个类是 `_BackendFasterWhisper`，热更新会把 trunk 当 model_name 加载 Whisper，**C 层 access violation 直接崩进程**（`sys.excepthook` 抓不到）。
- 已安装目录 `modules/installed/hot_reload.py` 已包含该修复，**但公开的插件市场/自动更新源还是旧版**。
- 本地验签 `tools/verify_signature.py --all` 48/48 通过。

### 修改

1. 确认 diff 只含这一处修复 + 对应重签；
2. 提交并推送 `modules_repo`（独立仓库，不影响主仓库 CI）；
3. 推送后核对远端 `manifest.json` 的 `sha256/signature` 与本地一致。

```bat
cd /d E:\xiaoliu\modules_repo
git status -s
py -3 ..\tools\verify_signature.py --all
git diff --stat
git add hot_reload.py manifest.json
git commit -m "修复热重载选类：跳过私有类，避免 whisper 加载崩溃；重签清单"
git push origin HEAD
```

### 验收（DoD）

- `verify_signature --all` 48/48；远端 `manifest.json` 与本地逐字节一致；
- `plugin_market.list_online()` 能列出 48 条；
- 新装用户从市场更新 `hot_reload` 后，版本与安装目录一致。

### 风险 / 回滚

- 只推清单不推模块文件 → 验签失败、市场拒绝安装。对策：`git add` 两个文件一起提交。
- 回滚：`git revert <sha>` 后重新 `py -3 ..\tools\sign_modules.py`。

## 二、P1：工作台 Git 暂存 / 提交 / 差异预览（约 1 天）

### 现状

`gui/ide_sidebar.py:266` `ScmPanel` 只有"分支 + 改动列表 + 双击打开文件"，**没有暂存、没有提交、没有 diff**。用户要看改了什么必须离开工作台。

### 目标

工作台内闭环：`搜索 → 改 → 看 diff → 暂存 → 提交`。

### 设计

**ScmPanel（`gui/ide_sidebar.py`，不新增文件）**

| 元素 | 类型 | 说明 |
|---|---|---|
| 提交信息框 | `QLineEdit`（占位「提交信息，Enter 提交」） | `returnPressed` → `commitRequested(msg)` |
| 「全部暂存」「提交」 | `QLabel` 链接（沿用「刷新」写法） | 不占按钮预算 |
| 右键菜单 | `QMenu + addAction`（不计创建点） | 查看差异 / 暂存 / 取消暂存 / 放弃改动（弹 `QMessageBox` 确认） |
| 状态着色 | 复用 `ide_explorer.git_status_map` | `??` 未跟踪、`M` 已修改、`A` 新增、`D` 删除、`MM` 部分暂存 |

新增信号：

```python
class ScmPanel(QWidget):
    openRequested = pyqtSignal(str)
    diffRequested = pyqtSignal(str)     # 绝对路径
    commitDone = pyqtSignal(str)        # 提交成功后的 sha
```

命令统一带 `-c core.quotePath=false`（中文路径已踩过坑），文件参数一律 `-- <rel>` 结尾。

**差异页（`gui/ide_editor_shell.py` `BottomPanel`）**

- `bar.addTab("差异")` + `QPlainTextEdit`（只读、Consolas），页签索引 3；
- `show_diff(path, text)`：`+` 行绿色、`-` 行红色、`@@` 灰色（逐行设置 `QTextCharFormat`）；
- 数据来源：已暂存 → `git diff --cached -- <rel>`；未暂存 → `git diff -- <rel>`。

**接线**

`SidebarHost` 增加 `diffRequested` 转发 → `WorkbenchWindow` 收到后调 `bottom.show_diff(...)` + `bottom.select(3)`；提交成功后在底部输出页追加一行 `[git] <sha> <msg>`。

### 测试计划（`tests/test_workbench.py`）

用临时目录 + `git init` 造真仓库（已有中文路径测试可复用 `_run_git` helper）：

1. 修改文件后 `refresh()` 列出该项、状态着色正确；
2. `stage()` 后 `git diff --cached` 输出含 `+` 新行；
3. `commit("msg")` 成功 → `git log -1` 的 sha 与 `commitDone` 一致；空信息/无暂存时拒绝并给出提示；
4. 非 git 目录：`refresh()` 显示「未检测到 Git 仓库」，不抛异常；
5. `BottomPanel` 页签数 3 → **4**，第 4 页标题「差异」（同文件现有断言要一起更新）。

### 验收（DoD）

- 工作台内可完成一次真实的「改 → diff → 暂存 → 提交」；
- 提交失败把 `git` 的 stderr 原样显示，不吞异常；
- 不新增任何按钮创建点（`check_buttons` 仍 60/60）。

### 风险

- `git add -A` 会连带无关文件：因此**只做逐文件暂存 + 「全部暂存」显式点击**，不做隐式全量提交。
- 提交信息含换行/引号：用 `git commit -m` 单参数传递，不拼 shell 字符串（`subprocess` 列表参数天然安全）。

## 三、P1：搜索增强——正则 / 区分大小写 / 替换（约 1 天）

### 现状

`SearchPanel.run_search()` 只做"关键词 → 结果列表"，`rg` 默认 smart-case、固定字符串；无替换；结果上限 100 条。

### 设计

| 元素 | 类型 | 行为 |
|---|---|---|
| `Aa` 开关 | `QLabel` 链接 | 点亮 = 区分大小写（`rg -s` / `re` 无 `I`）；默认不区分（`rg -i`） |
| `.*` 开关 | `QLabel` 链接 | 点亮 = 正则（不加 `--fixed-strings`）；默认字面量 |
| 替换行 | `QLineEdit`（默认隐藏，链接「替换」展开） | 第二行输入替换文本 |
| 「全部替换」 | `QLabel` 链接 | 执行前弹确认，显示将影响 N 个文件 |

实现要点：

- `rg` 参数按开关拼：`-i` / `-s`、`--fixed-strings`；正则模式下 `-e` 防模式以 `-` 开头；
- 兜底 `os.walk` 也走同一开关（`re.compile(pattern, flags)`），保证没有 rg 的机器行为一致；
- 替换前把命中文件复制到 `data/.x6_replace_backup/<时间戳>/`；跳过 `.git`、二进制（含 `\0` 探测）、>1MB 文件；
- 替换后刷新结果列表并提示「替换 N 处 / M 个文件」；
- 顶部「清空」继续可用。

### 测试计划

1. 大小写：`Foo`/`foo` 两文件，Aa 关闭命中 2 处、开启 1 处；
2. 正则：`\bpy_\w+` 命中变量名；
3. 替换：命中 3 处 → 文件内容被改、备份存在、计数正确；
4. 二进制与 `.git` 不参与替换；
5. `ide_sidebar.py` 行数 <600（超了按〇节拆分）。

### 验收（DoD）

- 三个开关状态在界面上可见（颜色区分），且与 rg/兜底两条路径结果一致；
- 替换失败不破坏原文件（先备份、后原子写）；
- 仍无按钮创建点新增。

### 风险

- 全局替换是破坏性操作：只允许在 `root` 内、必须二次确认、必须备份。
- 正则写错会匹配过多：确认框显示文件数 + 命中数，不显示"已完成"才落盘。

## 四、P2：编辑器诊断与补全（约 2 天，可拆两批）

### 现状

`gui/code_editor_widget.py` 只做 `.py` 的 `ast.parse`，把语法错误数量抛给状态栏；问题页只有行号；没有补全。

### 4.1 静态检查（0.5 天）

- 保存后后台 `QProcess` 调 `ruff check --output-format=json --quiet <file>`（`requirements-dev.lock` 已固定 ruff）；
- 有 ruff → 用其 JSON；没有 → 回退现有 `ast.parse`；
- 问题页条目改为「行 列 规则码 描述」，双击跳转；状态栏仍显示错误数；
- 只在保存/打开时跑一次，不做键入实时检查（避免卡顿）。

### 4.2 自动补全（1.5 天）

- `QCompleter` + 本文件符号表：`ast` 提取 `def/class/import as/赋值目标`，外加 Python 关键字与内置函数；
- 触发：安装 `QCompleter`（`PopupCompletion`），`Ctrl+Space` 手动弹出，键入 2 字符后 300ms 节流刷新；
- 只对 `.py` / `.js` / `.ts` 启用；注释/字符串内不弹（简单正则判断行首状态）；
- 不做 LSP、不做跨文件跳转定义（成本与风险不在本轮）。

### 测试计划

- 造一个含 `F401`（未使用 import）的临时 `.py` → 问题页出现条目、双击跳到正确行；
- 无 ruff 的机器（`PATH` 置空 + monkeypatch `shutil.which`）自动回退 ast，不崩；
- 补全：输入 `pri` 弹出 `print`；函数名 `foo` 在 `def foo` 之后可补全。

### 验收（DoD）

- 语法/静态问题能定位到行列；打开大文件（>5k 行）不卡主线程；
- 补全仅候选本文件符号 + 语言关键字，不误弹在注释里。

## 五、P2：终端持久会话（约 2 天）

### 现状

`BottomPanel.run_terminal()` 每条命令起一次 `QProcess(cmd /c …)`，无状态：`cd` 只改自建 `self.cwd`，交互式程序（python REPL）无法使用。

### 方案（两阶段）

**a) 持久 shell（1 天）**
- `QProcess` 常驻：Windows `cmd.exe /u /k chcp 65001>nul`；进程退出后回车自动重启；
- `readyReadStandardOutput` 流式追加到终端页；输入行写 stdin（`\r\n`）；
- `cd`/`cls`/`pwd` 仍本地处理（同步 `self.cwd` 与 shell 的 `cd /d`）；
- 清洗 ANSI 转义再显示（保留颜色可后置）。

**b) 真 PTY（可选，1 天）**
- 若安装 `pywinpty` 则用 ConPTY，获得 Tab 补全/颜色/交互；
- 未安装自动回退 a；依赖进 `requirements-optional` 与 `xiao6.spec` 的 hiddenimports。

### 测试计划

- 连续两条命令共享状态：`cd <tmp>` 后 `cd` 输出该临时目录；
- `echo` 中文不乱码；
- shell 进程被杀后自动重启；
- 无 pywinpty 环境不报错（回退路径）。

### 验收（DoD）

- 反复执行不需要重建进程；`python` REPL 在 a 阶段至少能进出、能执行单行；
- 关闭工作台不残留 shell 进程。

## 七、本轮明确不做

| 不做 | 原因 |
|---|---|
| LSP / 跨文件跳转定义 | 需引入语言服务器与进程管理，收益/风险不成比例 |
| 图形化调试器（断点/变量） | 属于另一个产品量级 |
| 多根工作区、远程开发 | 当前单项目使用场景，成本高 |
| Git 历史图 / 分支管理 | 只做暂存+提交+diff，其余留给命令行 |
| 终端 ANSI 全兼容（含 TUI 程序） | 依赖 PTY，放在批次 38 且为可选 |
