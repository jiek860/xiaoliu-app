一、整体架构
────────────────────────────────────────
微核星型架构：核心是core/trunk.py总线，所有模块通过trunk.call()调用，模块之间不直接互相import。
目录结构：
  项目根目录/
  ├─ gui\               # PyQt5全部界面代码
  │  ├─ app_pyqt.py     # 程序唯一启动入口
  │  ├─ build_ui.py     # 主窗口、侧边栏、输入框布局
  │  ├─ chat_view.py    # 聊天气泡渲染
  │  ├─ settings_dialog.py  # 设置窗口（常用/模型/界面/数据/高级5个标签）
  │  ├─ center_dialog.py    # 功能中心（分组列表样式）
  │  ├─ history_dialog.py   # 独立历史记录窗口
  │  └─ mixins/         # 界面逻辑拆分
  ├─ core\              # 核心微核
  │  ├─ trunk.py        # 总线：模块调度、回复主链路、后台队列
  │  ├─ llm_client.py   # 大模型客户端：本地Ollama+云端GLM三级路由
  │  ├─ vector_store.py # 本地向量知识库
  │  ├─ config.py       # 配置读写+自动数据迁移
  │  ├─ crypto.py       # 加密：本地随机密钥，兼容旧XOR
  │  ├─ backup.py       # 自动备份（备份前自动合并SQLite WAL）
  │  ├─ paths.py        # 统一路径管理，跨平台无硬编码
  │  ├─ chat_store.py   # 聊天记录SQLite存储
  │  ├─ base_module.py  # 插件模块统一基类
  │  └─ version.py      # 版本号v25.1.6
  ├─ modules\installed\ # 所有功能插件
  ├─ data\              # 运行时数据：配置/聊天记录/日志/备份
  ├─ requirements.txt    # 核心依赖清单
  ├─ install.bat        # 朋友一键装依赖
  └─ check.bat          # 一键自检脚本

四、核心调用链路
────────────────────────────────────────
用户发消息 → gui/chat_view.py发送 → trunk.reply()
  → _reply_inner()：优先走pipeline流水线
    1.  并行检索：向量库搜索、记忆召回
    2.  组装Prompt：人格设定+系统提示+历史+检索结果
    3.  llm_client路由选模型：短消息→小模型，带图→视觉模型，复杂→云端
    4.  流式输出回复到聊天框
  → 后台队列异步处理：记忆沉淀、备份、学习
  → 如果pipeline异常，自动降级到旧回复逻辑，不会崩
